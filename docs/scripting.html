Scripting reference

Halo Map Studio has a small line-oriented command language ("Forge script") for placing and editing objects, driving the camera, loading maps and variants, and taking screenshots. The same grammar is used by the in-app console, script files run from the command line, and the MCP server.

Ways to run a script

Entry pointHowNotes
Script console (GUI)View ▸ Script console (or Tools ▸ Script console…, or the ⌨ Script toggle in the toolbar). Type or paste commands into the editor and press ▶ Run.The editor starts pre-filled with a commented quick reference. The output log appears below. One run = one undo step. There is no "run file" button — paste the file's contents.
Script file (headless)hms-app --script build.hscrNo window is opened. The log is printed to stderr. Any file extension works (.hscr, .txt, .hms). Exit code 0 on completion.
One-liner (headless)hms-app --exec "loadmap forge_halo" "camera frame" "screenshot out.png 1280x720"Everything after --exec is joined with spaces into one script; use newlines inside the quoted string for several commands.
TCP command serverThe GUI listens on 127.0.0.1:47800 (change with HMS_CMD_PORT=<port>, disable with HMS_CMD_PORT=0).Length-framed text: send <byte count>\n<script>, receive <byte count>\n<log>. Each request is one undo step. Used by the MCP server below; you can also talk to it from any language.
MCP serverhms-mcp bridges an MCP client (an LLM agent) to the command server.See below.

The GUI executor and the headless executor share one grammar, but a few commands need the interactive app (they are marked GUI only) and headless loads are synchronous while GUI loads stream over frames (marked where it matters).

Grammar

  • One command per line. Lines are split on whitespace; there is no quoting. Where a value may contain spaces (labels, paths, echo text) the command takes the rest of the line.
  • Comments: a line starting with # or // is skipped. Blank lines are skipped. No trailing comments.
  • Case: command words and keywords are case-insensitive. Name filters are case-insensitive substring matches.
  • Numbers are decimal floats (1, -2.5, 1e3). Vectors are three separate numbers: X Y Z, not x,y,z.
  • Units: positions and distances are world units — the same numbers the Object panel and the camera readout show; angles are degrees.
  • Datums identify objects: hexadecimal 0xD8000001 or decimal. Variant objects are 0xD0xxxxxx, objects placed by scripts 0xD8xxxxxx. Get them from list objects.
  • Palette references for place: #<index> (from list palette) or a case-insensitive substring of the item name (first match wins). Palette names use underscores (block_2x2_flat, wall_double); a name with a space is read as two words, so place block 1x1 fails with unknown place target '1x1'.
  • Directions: +x -x +y -y +z -z, with aliases east west north south up down. Faces (for coincident) additionally accept left right front back bottom top or the numbers 0–5.
  • Filters (for list objects, count, foreach objects): any of type <t>, name <s>, label <s> in any order.
  • A bad line prints an error and the script continues with the next line.
  • Undo: in the GUI a whole run is one undo step, except a run that itself contains undo or redo — that run takes no snapshot of its own, so its undo acts on the previous real edit, exactly like Ctrl+Z.

Placing objects

place <name|#idx>                         # on the surface under the camera crosshair (12 units ahead if nothing)
place <name|#idx> at X Y Z
place <name|#idx> rel <datum> DX DY DZ     # at another object's position plus an offset
place <name|#idx> onface <datum> <dir>     # flush against that object's face in direction dir
place <name|#idx> camera

The new object gets identity orientation, the neutral team (8, what the game gives every new Forge placement), inherited colour and the default Forge flags, becomes the selection, and is fully editable and saveable. Output: placed 'block_1x1_flat' → 0xD8000000 at (10.0,20.0,60.0) — always read the datum back from this line rather than assuming it. Errors: no palette object matching '…', palette index N out of range, no object 0x…, unknown place target '…'.

Editing objects

CommandEffect
select <datum> · select all · select none · deselectSet the selection. Prints selected 0x… / selected N objects.
select box X1 Y1 Z1 X2 Y2 Z2 [add]Box-select in world space: every variant / placed object whose bounds (a hidden block's physics hull) overlap the axis-aligned box between the two corners — the same test the viewport's rubber band uses. add keeps the current selection.
delete [datum]Delete the object, or the whole selection when no datum is given. del is an alias.
move <datum> DX DY DZMove by a delta.
moveto <datum> X Y ZMove to an absolute position.
rotate <datum> <x|y|z> <deg>Rotate about the given world axis through the object's own position, in degrees (right-hand rule; the Object panel's X/Y/Z fields use the same convention). rot is an alias.
dup [datum] [DX DY DZ] GUI onlyDuplicate the object (or the selection) with an optional offset; the copies become the selection. duplicate is an alias.
settle [datum | all | selection]Drop the object(s) onto the surface below and tilt to the slope ("simulate physics"). drop is an alias.
pick [delete] [radius <wu>]Select (or delete) whatever is under the camera crosshair, plus everything within radius of it. aim is an alias. The reply names the hit: under crosshair: 0xE0000005 objects\props\…\health_cabinet (scenery, tag 0x00fc, scnr #5) — 1 object(s) selected.
count [filters]Count matching objects; in the GUI also reports the slot budget: N object(s) match — variant holds T/651 (F free). (Headless: prints N object(s) and the name/label filters are not applied.)
undo · redo GUI onlyStep the editor's edit history, the same stack as Ctrl+Z / Ctrl+Y. Prints undo / redo, or undo: nothing to undo. Headless answers ERROR undo/redo: the headless batch host keeps no edit history.

Output: set 0x… team=1 or set team on N object(s). Errors: unknown field '…', team must be -1..8, bad team '…', expected on|off|default, got '…', no editable object 0x…, set selection: nothing editable selected.

coincident (face mate)

coincident <datumA> <faceA> <datumB> <faceB> [centered] [noturn]

Needs the objects' mesh bounds, which the interactive app has after the scene is built. In a headless --script run, objects placed in the same run currently answer coincident: no bounds for 0x…; use it from the GUI console or the MCP server.

Moves object A (only A moves) so that its face faceA becomes coincident with face faceB of object B — the CAD "mate" from the Construction window. By default the mate is flush (coplanar; A keeps its position within the plane) and A is turned so the faces oppose each other. centered (also centred, center, centre) additionally aligns the face centres; noturn (also norotate, slide) keeps A's rotation. Faces: -x +x -y +y -z +z, the words left right front back bottom top, or 0–5. mate is an alias.

# stack the second block on top of the first, centred
coincident 0xD8000001 -z 0xD8000000 +z centered

Errors: coincident: no bounds for 0x…, coincident: 0x… face N has no normal (zero-extent axis).

Display and global switches

These verbs mirror checkboxes in the View menu and the Settings window. Each takes on / off (also 1/0, true/false) or get (or nothing) to report the current state. In the GUI a change is persisted like the checkbox (see where settings live); in a headless run it applies to that run only.

CommandMirrorsEffect
screenfx on|off|get (forgefx, fx)Settings ▸ Forge special FX (default on)Apply the screen effects of placed Forge special-FX objects (Colorblind, Gloomy, Juicy, Nova, Olde Timey, Pen and Ink, Dusk, Eerie, Golden Hour). Off = the map's own default effect only. Reports Forge FX: dusk + juicy or Forge FX: none placed (on).
scale on|off|get (scaled, scaling)Settings ▸ Scaled objects (default on)Global switch: objects whose SCALED flag is on render at the size their spawn sequence encodes. Off = every object at x1. (Different from set <datum> scale N, which writes the size.)
shadowcasters on|off|get (shadowcaster, casters, shadows)Settings ▸ Shadow casters (Forge) (default on)Global switch: objects whose SHADOW flag is on are drawn into the sun shadow map. Off = only the engine's default casters (vehicles, weapons and so on) cast.
mapspawns on|off|get (map_spawns, scnrspawns)View ▸ Show map spawn points (default off)Draw the base map's own built-in spawn markers (respawn points, respawn zones, spawning cameras). They are not part of your variant and cannot be edited or saved; your placed spawn points always show. Reports how many markers are hidden or drawn.
outlines on|off|get (outline, physoutlines, physics_outlines, blockers)View ▸ Show hidden-block physics hulls (default on)Draw the physics hull (orange volume plus outline) of every hidden block the variant placed — the invisible walls a shipped variant seals the map with. On by default so the blocks can be found and edited; off gives the game's look. Only variant/user-placed pieces ever get a hull. Reports the hull triangle count.
flags [get] (flag)—Report both globals (scale on | shadowcasters off | N scaled, M casting | shadow pass: …) followed by one line per selected object with its effective SCALED / SHADOW state and whether each is automatic or set.
bspwarn [list] (bsp_warn, bspflags)The save-time warning windowPrint the map's structure BSPs with their playable-space flags, then every variant / placed object whose position is inside a BSP marked "not normally playable space in multiplayer" — the same list the GUI shows before a save (see Objects outside playable space). Error no map loaded.

Batch renders can set the same switches from the environment (HMS_FORGE_FX, HMS_SCALED, HMS_SHADOWCASTERS, HMS_MAP_SPAWNS, HMS_PHYSICS_OUTLINES) — see Headless / CLI.

Queries

CommandOutput
list palette [filter] (pal)N palette objects: then #idx name lines (truncated after 200 in the GUI, 400 headless).
list objects [type t] [name s] [label s] (also plain list, objects)N objects: then 0xDATUM (x,y,z) type=N name [label]. The map's own scenery appears as 0xE0xxxxxx entries headless. (Headless: name/label filters are not applied.)
list typesDistinct object types with counts.
list maps [filter] [stk|mod] id=0x… label for each detected map.
list variants [current | <map id> | map <name> | all] [filter]Variants in the catalogue: the mvars/ folder next to the executable plus every folder in HMS_MVAR_DIRS (searched recursively; ;-separated). Filter matches the file stem.
get <datum> (info)Everything about one object: position, forward/up, tags, name, team, colour, type, spawn sequence, respawn, label, boundary, scale, placement flags, weapon clips, teleporter channel, location name. Maps, variants, screenshots, saving

CommandEffect
loadmap <name | stem | substring | path> (openmap)Load a map. Headless: synchronous. GUI: the load streams over the following frames.
loadvariant <path> (openvariant, loadmvar)Open a variant; its base map is loaded automatically from the map id. Headless output includes the object count and which camera pose was chosen.
waitHeadless: no-op (loads are synchronous). GUI: prints a reminder that loads stream over frames — a GUI script cannot block on a load, so run load-then-screenshot batches headless.
screenshot <path | dir> [WxH | W H] (shot, snap)Write a PNG. If path is a directory (or ends in /) the file is named after the last loaded variant/map stem. Parent folders are created. Headless honours the size; the GUI captures the live viewport at its own size.
save · save as <path> · saveas <path> GUI onlyWrite the open variant in place, or to a new file (which becomes the open variant). Output saved N objects → path, with — WARNING: N object(s) outside playable space (see `bspwarn list`) appended when the save-time check would have warned (a scripted save never blocks). Error: no variant is open — use `save as <path>`.

save overwrites the open .mvar without a backup, exactly like File ▸ Save.

Loops

foreach <source> as $v
  …
end

Sources: variants [current | all | <map id> | map <name>] [filter], maps [filter], objects [type t] [name s] [label s]. Inside the body $v is the item (a path for variants and maps, 0xDATUM for objects), $stem is the file stem (or object name) and $idx the 0-based index. Loops nest up to 16 deep. A missing end aborts the block with ERROR foreach without matching 'end'.

Output format

Every line produces at most one result line. Successful commands print their message with no prefix; execution errors are prefixed ERROR ; unparseable lines are prefixed PARSE (for example PARSE unknown command 'foo'). If a run prints nothing at all the log is ok. In the GUI the log appears in the console's Output box; over TCP it is the response body; headless it goes to stderr.

Examples

Build a small platform

list palette block                      # find the exact names / indices
place block_2x2_flat at 10 20 60        # → placed 'block_2x2_flat' → 0xD8000000 at (10.0,20.0,60.0)
place block_2x2_flat onface 0xD8000000 +x
place block_2x2_flat onface 0xD8000000 -x
place block_1x1 rel 0xD8000000 0 0 5    # 5 units above the first block
rotate 0xD8000003 z 45
select all
set selection team 1
set selection color -1
count

Recolour every object with a label

foreach objects label ctf_flag_return as $o
  set $o team 0
end

Mark a pair of pieces as scaled shadow casters

select 0xD0000012
set selection shadow on            # SHADOW (set) on every selected object
set 0xD0000012 scaled default      # back to automatic (follows the "scale" label)
flags                              # globals + the selection's effective flags
shadowcasters off                  # global switch: no Forge piece casts (persisted in the GUI)
undo                               # GUI only: steps the real edit history

Batch screenshots of every variant (headless)

# shots.hscr — run with: hms-app --script shots.hscr
foreach variants all as $v
  loadvariant $v
  camera frame
  screenshot out/$stem.png 1280x720
end

A fixed camera on Forge World

loadmap forge_halo
wait
camera to 40 -70 104.5
camera lookat 40 -260 101.5
screenshot forge_ground.png 1280x720

MCP server (hms-mcp)

hms-mcp is a small Model Context Protocol server (JSON-RPC over stdio) that lets an LLM agent such as Claude drive the running editor. It is a thin bridge: every tool call is turned into a script and sent to the GUI's TCP command server, and the editor's log comes back as the tool result. It is built from the same repository (cargo build --release -p hms-mcp); a prebuilt binary is not part of the v0.1.0 archives, so treat it as a power-user feature.

  1. Start the editor (hms-app). The command server listens on 127.0.0.1:47800 (or HMS_CMD_PORT).
  2. Register hms-mcp with your MCP client. Example mcpServers entry for Claude Desktop / Claude Code:
{
  "mcpServers": {
    "hms-forge": {
      "command": "C:\\path\\to\\hms-mcp.exe",
      "env": { "HMS_CMD_PORT": "47800" }
    }
  }
}

HMS_MCP_TARGET=host:port overrides the whole address if the editor runs elsewhere. Tools exposed:

ToolParametersPurpose
forge_scriptscript (string, newline-separated commands)Run any commands from this page. Returns the per-line log. One undo step per call.
list_palettefilter (optional)Placeable palette objects with their indices.
list_objects—Scene objects with datum and position.
place_objectname, x, y, zPlace a palette object (name substring or #index) at a world position; returns its datum.

Because it drives the live window, a loadmap followed immediately by screenshot may capture mid-load; use hms-app --script for deterministic batches.
