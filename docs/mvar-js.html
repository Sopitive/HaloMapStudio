Map variant JavaScript API

hms-mvar.js reads Halo map variants (.mvar) in a web page or in Node: the header and metadata, the map, bounds, budget, quotas, Forge labels and every placed object with its position, rotation, team, label and physics, for Halo: Reach, Halo 3, Halo 4 and Halo 2 Anniversary. It is one file with no dependencies, no network access and no build step. Try it in the web viewer.

Decode only. The library reads variants; it does not write or edit them (use Halo Map Studio for that). It contains no game data, so object names need a palette table you supply (below).

Quick start

There are two files in this site’s js/ folder, with identical code and API:

  • js/hms-mvar.js — an ES module (for import, Node ESM, bundlers).
  • js/hms-mvar.classic.js — the same code as a plain script: no import, no type="module". It works when a page is opened from disk (file://) and from a web server. It is generated from the module by js/build-classic.mjs (node docs/js/build-classic.mjs), and a test fails if the two ever differ.

Mode 1: double-click (a page opened from disk)

Save the page and the js folder together. A plain script tag is all it takes; the global HmsMvar appears:

<input type="file" id="f">
<script src="js/hms-mvar.classic.js"></script>
<script>
  document.getElementById('f').onchange = async (e) => {
    try {
      const v = await HmsMvar.parseFile(e.target.files[0]);   // File or Blob
      console.log(v.game, v.header.title, v.objects.length, 'objects');
      console.log(HmsMvar.toCSV(HmsMvar.filterObjects(v, { paletteIndex: 12 })));
    } catch (err) {
      if (err instanceof HmsMvar.Error) alert(err.code + ': ' + err.message);
      else throw err;
    }
  };
</script>

The viewer is built exactly this way. (A browser will not load an imported module from a file:// page, which is why this build exists.)

Mode 2: on a web site or GitHub Pages

The same <script src="js/hms-mvar.classic.js"> works on a site served from a sub-path such as https://sopitive.github.io/HaloMapStudio/, because every URL is relative (no leading /). If you prefer modules there: <script type="module"> import HmsMvar from './js/hms-mvar.js'; </script> (this needs http(s), not file://).

Mode 3: Node and bundlers

// ESM
import fs from 'node:fs';
import HmsMvar from './hms-mvar.js';
const v = HmsMvar.parse(fs.readFileSync('my_map.mvar'));   // Buffer / Uint8Array / ArrayBuffer
console.log(v.game, v.map.mapId, v.objects.length);
console.log(HmsMvar.countBy(v.objects, 'paletteIndex'));
fs.writeFileSync('objects.csv', HmsMvar.toCSV(v.objects));

// CommonJS
const HmsMvar2 = require('./hms-mvar.classic.js');

API

CallReturns
HmsMvar.parse(bytes)The parsed variant (below). bytes is an ArrayBuffer, Uint8Array or Node Buffer. Synchronous.
HmsMvar.parseFile(blobOrFile)A promise of the same, for a File / Blob.
HmsMvar.ErrorThe error class every refusal uses. .code is bad-input, not-mvar, truncated, unsupported, corrupt or too-large.
HmsMvar.filterObjects(parsed, filter)The matching objects. Filter keys (all optional, all must match): paletteIndex (number or list), name (substring or RegExp; needs a palette), label (substring or RegExp), team (number, list, or null for none), physics ('normal', 'fixed', 'phased'), objectType, box ({min:[x,y,z], max:[x,y,z]}), near ({x,y,z,radius}), predicate (o => boolean).
HmsMvar.countBy(objects, key)An object of counts, {"12": 41, ...}. key is a property path ('paletteIndex', 'placement.physics') or a function.
HmsMvar.toCSV(objects, opts)RFC 4180 text (CRLF). Text cells that start with = + - @ get a leading apostrophe so a spreadsheet does not run them as formulas; pass {safe:false} to switch that off. {columns:[...]} picks columns.
HmsMvar.toJSON(parsed, space)A JSON string of the whole result.
HmsMvar.withPalette(parsed, table, opts)The same parsed with .name on every object and quota. See names.

The parsed variant is plain data: game ('reach', 'halo3', 'halo4', 'h2a'), blf (chunk list, mvar chunk version, stored length and SHA-1 check), header (title, description, author, editor, created and modified stamps, category, ids), map (mapId, mccMapId, paletteCrc, version, ...), bounds (xMin..zMax, plus min / max arrays), budget (max, spent), quotas, labels, objects, extra and warnings. 64-bit ids (uid, xuid, ...) are 16-digit hexadecimal strings, never BigInt. Timestamps are Unix seconds with an ISO date beside them.

The object record

FieldMeaning
index, slotPosition in objects; the slot in the file (parentSlot of another object refers to it).
paletteIndexWhich palette entry (Reach / Halo 4: the quota index; Halo 3: the quota index, null for a base-map object). variantIndex is the variant inside the entry (Reach, Halo 4).
x, y, zWorld position. Stored quantised to the variant’s bounds, so these are the exact values the game would read.
forward, up, yaw, pitch, rollOrientation; see Rotation.
team0..7 the team colours, 8 neutral, null none (Halo 3: the stored byte).
label, labelIndexThe Forge label text (Reach: one; Halo 4 / H2A: labels lists up to four).
placement{raw, physics, symmetry, placedAtStart, uniqueSpawn, ...}. physics is 'normal', 'fixed' or 'phased' (Reach, Halo 4, H2A; null for Halo 3).
spawnSequence, respawnTimeThe Forge spawn sequence and the respawn time in seconds (Halo 3 has only the respawn time).
objectTypeThe multiplayer object type number (a position in the game’s own list).
shape{type: 'none'|'sphere'|'cylinder'|'box', raw, values}. raw are the stored quanta; values are world units for Halo 3 and Halo 4 / H2A and null for Reach, where HMS does not decode a unit.
color, extraColour override; type-specific fields (weapon clips, teleporter channel, scale and lock for Halo 4, ...).
rawThe exact stored fields (quanta, flags) for anyone who wants the bits.

Rotation

The file stores the up vector (a flag for “straight up”, otherwise a quantised unit vector) and a forward angle about it. forward and up are decoded exactly as Halo Map Studio decodes them. yaw, pitch and roll (degrees) are derived by this library from those two vectors: yaw is atan2(forward.y, forward.x), pitch is the elevation of forward, and roll is the turn of up about forward relative to the up that a zero-roll object with that forward would have. Use forward / up if you need the stored orientation itself.

Names and the palette table

A variant stores palette indices. The names belong to the game’s map, so they are not embedded in this library. Supply a table with withPalette:

{ "game": "reach", "mapId": 3006, "names": ["Walls / Wall, double", "Blocks / Block 2x2", "..."] }   // one map
{ "maps": { "3006": { "game": "reach", "names": ["..."] } } }                                          // several maps
[ "name0", "name1" ]                                                                                  // bare array (no checks)

names[i] is the name of palette index i, which is also quota i. If the table says it is for another game or map id, nothing is applied and a warning is added (override with {force:true}).

Making the table with Halo Map Studio

Reach and Halo 4 are supported. The script verb variant get palette-json prints the table as one JSON object. Headless (needs the game installed so HMS can read the map):

hms-app --exec $'loadvariant /path/to/my_map.mvar\nvariant get palette-json'

loadvariant loads the variant’s base map automatically; the log goes to stderr, so redirect it (2>table.log) and copy the single JSON line into a .json file. In the app’s console the same command prints it on screen. The names are the same ones the Quota table in variant get shows (category / name). A table is per map, so make it once per base map and reuse it for every variant on that map. The verb itself is covered by a unit test; the end-to-end headless run is described here as the intended route and has not been exercised by an automated test. Halo 3 and H2A names are not produced by HMS yet (their index is still listed by variant get); you can write the table by hand.

A Halo 4 or H2A title that is a localisation key ($h4_mvar_..._name) is returned as the key, with header.titleIsKey set; the text lives in the game’s own string tables. A Reach or Halo 4 file stored inside a compressed _cmp chunk is expanded automatically.

Bad input

Anything that is not a readable variant throws an HmsMvar.Error with a code and a plain-language message; the library never lets a raw RangeError or TypeError escape from a damaged file and never loops on one. A file with flipped bits can still be a valid variant with different values; check warnings (for example a stale SHA-1) if the source is untrusted. Strings from a file (titles, labels) are untrusted text: put them in the page with textContent, not innerHTML.

How it is tested

The JavaScript is a port of Halo Map Studio’s own Rust decoders and is tested against them. A Rust test (crates/hms-app/src/mvar_json_dump.rs, ignored by default) decodes a list of folders with the real parsers and writes every field of every file as JSON, with each 32-bit float as its raw bits. docs/js/test/hms-mvar.test.mjs (plain node, no dependencies) parses the same files with hms-mvar.js and compares field by field. On the author’s machine that covered 2514 variants (895 Reach, 666 Halo 3, 778 Halo 4, 175 H2A; the shipped sets of three installs plus game-saved files) with every field identical in all of them; the one remaining file has no variant chunk at all and both decoders refuse it. Positions and all stored values are bit-identical; the Halo 3 forward vector differs in the last bit of one component for some objects (a difference between the platform’s and JavaScript’s single-precision sine and cosine, at most 1.2e-7), and the test states that tolerance for the orientation vectors only. The same test cuts files short at many points and flips thousands of bits, and requires a clean HmsMvar.Error or a normal result every time. The classic and module builds are additionally checked against each other (docs/js/test/classic.test.mjs: the committed classic file must equal what the build script makes, and both decode sample files of every game identically), and the same equivalence run passes on the classic build. The test files themselves are never copied into the repository.

The map renderer (hms-render.js, hms-camera.js, hms-gl.js)

Three small plain scripts (they work from file:// and from a web site, with no library and no network) draw a parsed variant: hms-render.js is the view (top-down Canvas 2D, overlay, picking, the Canvas fallback for 3D), hms-camera.js is the camera maths and input controller, hms-gl.js is the WebGL renderer. The viewer uses all three. It is meant to show roughly what the map looks like, not to be a game renderer: no PBR, no lightmaps, no specular or environment maps, no bump maps.

<canvas id="gl"></canvas><canvas id="map" tabindex="0"></canvas>   // stack them: the 2D canvas on top, transparent
<script src="js/hms-mvar.classic.js"></script>
<script src="js/hms-camera.js"></script><script src="js/hms-gl.js"></script><script src="js/hms-render.js"></script>
<script>
  const view = HmsRender.create(document.getElementById('map'), {
    glCanvas: document.getElementById('gl'),   // optional; without WebGL the Canvas painter is used
    describe: (i) => 'object ' + i,            // text for the hover label
    onSelect: (i) => console.log('clicked', i) // i = the object's .index, or null
  });
  view.setVariant(HmsMvar.parse(bytes));      // markers over the map bounds: needs nothing else
  view.setPack(pack);                         // optional render pack: meshes, materials, height shading
  view.setVisible(filtered.map(o => o.index)); // draw only these; the rest are faded
  view.setTransparency(true); view.setHideCats(['shield', 'glass', 'glow']); view.setGhost(true);
</script>

3D picking is by ray against each object’s oriented box with depth, hover highlights, and a click selects (the viewer highlights the matching table row and a row click selects the object). A small axis gizmo shows the orientation. Near and far planes follow the zoom, so nothing clips when you are very close or very far.

Drawing

  • 3D, WebGL (1 or 2): instanced meshes with a depth buffer, hemisphere plus directional light, flat shading, a lit terrain from the pack’s height grid, a ground grid and bounds, frustum culling, an outline for the selected and hovered object (also through glass). If WebGL (or instancing) is not available, a Canvas painter draws oriented boxes instead (the page works the same, only plainer).
  • Materials (pack v2): opaque parts and alpha-test cutouts (foliage, fences, texture holes) draw first with depth writes; blend parts (glass, windows) and additive parts (force fields, glows) draw afterwards, sorted far to near per object, with depth test on and depth write off, premultiplied alpha / additive blending, and no back-face culling. A part shows its diffuse colour (the diffuse map’s average) and, when the pack has it, a tiny texture, lit only by the hemisphere and sun term. Colour by “material” shows that; “category”, “team” and “physics” recolour the instance but keep the transparency.
  • Transparency checkbox: off draws every part as an opaque surface. Shields / glass checkbox: hides the translucent categories (shield, glass, glow) entirely.
  • Filtered-out objects (they do not match the table filters) are drawn as a flat, desaturated, faded silhouette so they cannot be mistaken for real transparency; the Faded filtered-out checkbox hides them instead.
  • Performance: it culls to the view frustum and batches by mesh; on a real GPU thousands of instances are not a concern. Software GL in headless Chromium takes about 200 ms for 5000 instances of 160 triangles each (800 000 triangles); it is much faster for plain boxes. The pure maths (box corners, projection, picking, camera, pack and mesh decoding) is unit-tested in plain Node (docs/js/test/render.test.mjs, camera.test.mjs).

The render pack

A render pack is derived from your own installed game. Keep it for yourself; do not redistribute it, commit it, or put it on a web site. The Halo Map Studio repository and this site ship no pack and no game data. The viewer reads a pack from your disk, keeps it in memory only, and never uploads it.

A pack is deliberately small and abstract: per object type a simplified mesh (at most 400 triangles) with one minimal material per part, a coarse height grid, and no triangle soup of the level, no full-size model, no full-size texture, no shader. Format version 2 (JSON; version 1 packs, which hold boxes and the grid only, still load). Forge World: 145 palette entries, about 2.4 MB (limit 2.5 MB; the generator shrinks triangle budgets and drops textures to fit, never the alpha modes):

{
  "format": "hms-render-pack", "version": 2, "game": "reach", "mapId": 3006,
  "bounds": [xmin, xmax, ymin, ymax, zmin, zmax],
  "palette": [ {                       // one entry per palette (quota) index
      "i": 79, "name": "structure_blocks", "cat": "block",   // cat: block scenery weapon vehicle equipment device spawn zone shield glass glow other
      "box": [minx, miny, minz, maxx, maxy, maxz],          // local axis-aligned box, +x forward, +z up
      "mesh": { "box": [...], "n": 24, "tris": 12, "ib": 8,  // n vertices, int16 x,y,z inside "box"; indices u8 (ib 8) or u16 (16)
                "v": "<base64>", "i": "<base64>",
                "uv": "<base64 u16 pairs>", "uvb": [u0, v0, u1, v1],   // only when a part has a texture
                "parts": [ { "lane": "opaque", "c": [r, g, b], "o": 1.0, "t": 0, "s": 0, "n": 12 } ] },
      "variants": [ { "v": 0, "name": "block_1x1", "cat": "...", "box": [...], "mesh": {...} } ]   // only when an entry has several sizes
  } ],
  "textures": [ { "w": 16, "h": 16, "rgba": "<base64 RGBA8>" } ],   // tiny diffuse maps shared by parts; optional
  "grid": { "w": 128, "h": 128, "zmin": -25.0, "zmax": 117.8, "min": "<base64>", "max": "<base64>" }
}

A part is a triangle range [s, s+n) of the mesh with lane = opaque, cutout (alpha test), blend (glass, windows) or additive (force fields, glows), a base colour c (the diffuse map’s average, 0 to 255), an opacity o and an optional texture index t. The lane is the one Halo Map Studio’s own scene routes the shader to, from the shader tag’s authored blend type, alpha test, glass, halogram and forcefield class. It is never guessed from a name.

cat is a guess from the tag class and palette name for the colour, except these: shield is a model that is mostly a forcefield (the Forge one-way and two-way shield doors, the laser walls, the hangar shield pieces), or an effect-drawn volume (a render model of 4 triangles or fewer, with a physics hull and an effect attachment: a translucent cool-tinted hull panel is emitted for it); glass is a model that is mostly alpha-blended; glow is mostly additive. A weapon with one translucent scope lens stays a weapon. The mesh is the object’s render model where its box agrees with the physics hull’s box (weapons, vehicles, scenery), else the physics hull itself (blocks, walls, ramps and the hidden blockers, where convex hulls are essentially exact). The height grid holds, per cell of the world bounds, the lowest and highest Z of the level’s collision triangles that touch the cell, quantised to 8 bits over [zmin, zmax].

Making a pack with Halo Map Studio

Reach and Halo 4 variants; the game must be installed so HMS can read the map:

hms-app --exec $'loadvariant /path/to/my_map.mvar\nvariant get render-pack my_map.pack.json'

It writes the file and prints a one-line summary (entries, boxes, size). Make it once per base map; it serves every variant on that map. Halo 3 and H2A packs are not produced (HMS has no palette-to-geometry route for them), but a variant of those games still draws as markers, and the pack format simply omits what it does not have.

The viewer also lists which entries a pack classified as shield or glass (the generator prints the list: translucent entries (n): ...). How the generator is checked: an ignored, map-backed Rust test (render_pack::tests::render_pack_gate_forge_world) builds the pack for Forge World with the same function the verb calls and asserts the size (≤ 200 KB; measured 75 KB), that nearly every palette entry has a box, known proportions (block_1x1 is a 1.016 × 1.016 × 1.0 cube, block_4x4 is 4 × 4 × 1, the Forge grid object is 30 wide), that every entry has a mesh within the 400-triangle and 2.5 MB budgets, that the one-way and two-way shield doors are classified shield with only translucent parts while a solid block and the heavy barricade (whose tag path contains “shield”) stay opaque, and that the height grid cell under each of a real variant’s objects equals a direct query of that cell (a transposed grid fails it). The verb itself has not been run end to end in this environment.

Limits

  • Decode only. No encoder, no editing. The map view is a rough overview (boxes and a coarse height grid), not a faithful render; objects with no box in the pack are shown at a default size.
  • No game data: names need your palette table; Halo 4 localisation keys stay keys.
  • Reach boundary-shape sizes are not converted to world units (HMS does not do it either); the stored values are in shape.raw.
  • Halo 3 records have no physics, spawn-sequence, colour, label or scale field; the flag byte is decoded as described in the table above and the raw bytes stay in placement.raw and raw.
  • Browsers: tested in headless Chromium only (from file:// and from a sub-path web server); Firefox and Safari are untested. Needs ES2020 (BigInt, TextDecoder).
  • Files over 64 MiB are refused.
