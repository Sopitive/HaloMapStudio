Requirements

  • Halo: The Master Chief Collection (Steam) with the Halo: Reach content installed. The app reads the game's own .map cache files; it does not ship any game content and cannot run without the game.
  • GPU: Vulkan on Linux; DirectX 12 or Vulkan on Windows. Discrete GPUs are preferred over integrated ones automatically. If no hardware adapter is found the app falls back to a software rasteriser (lavapipe on Linux, WARP on Windows) — it works but is far too slow for interactive use.
  • Memory: loading Forge World peaks around 4.5 GB and settles to about 1 GB. 8 GB of system RAM is a sensible minimum.
  • OS: Windows 10/11 x64 or a 64-bit Linux desktop. On Linux the Steam (Proton) install of MCC is detected like any other Steam library.

Steam Workshop maps are listed separately from the built-in ones. Xbox / Microsoft Store installs are probed only when no Steam install is found (see map discovery).

Install

Download the archive for your platform from GitHub Releases (halo-map-studio-rust-0.1.0-windows-x64-<date>.zip / …-linux-x64-<date>.zip). There is no installer.

Windows

  1. Unzip anywhere (for example %USERPROFILE%\Tools\HaloMapStudio\).
  2. Run hms-app.exe. Keep HaloMapStudioDLL.dll next to it — it is the native map parser.

Linux

  1. Unzip anywhere and make the binary executable if needed: chmod +x hms-app.
  2. Run ./hms-app. Keep libhalomapstudio.so next to it.
  3. If your Steam library is somewhere unusual, point the app at it: HMS_MCC_DIRS=/path/to/steamapps/common/Halo\ The\ Master\ Chief\ Collection ./hms-app.

The archive also contains LICENSE.md, COMMERCIAL-LICENSE.md, THIRD-PARTY-NOTICES.md and a short README.md.

First launch

  1. The app scans your Steam libraries for MCC and lists every playable map in the Map section of the left panel: first pick the game (Reach, Halo 4, Halo 2 Anniversary — only the ones you have), then Built-in or Modded within it. If nothing is listed, see No maps detected.
  2. Pick a map from the drop-down and press Load selected map. Forge World takes a few seconds; a progress bar runs along the bottom.
  3. Hold the right mouse button in the viewport and use WASD to fly (see Camera & navigation).
  4. To edit a Forge map: File ▸ Open .mvar…, pick a variant, and the base map is loaded automatically if it is not already open. See Maps & variants.

The last map and the last variant you opened are remembered and reopened on the next launch.

The main window

UI is being reorganised. The layout below is the target layout of the current development branch; labels and screenshots may lag the build you have.

  • Menu bar: File (variants and projects), Edit (undo/redo, select all, deselect, delete, remove all placed objects), View (frame selected object, screenshot, Construction panel, Script console, then everything that is DRAWN: geometry — BSP, Terrain, Forge objects, Water, Sky; Forge extras — Forge special FX, Scaled objects, Shadow casters; overlays — Grid, Lights, Boundary shapes, Collision and Physics of the selection, Show map spawn points, hidden-block physics hulls, Selection wireframe through objects, Trigger volumes, Soft ceilings, Hard floor, Playable BSP bounds), Tools (placement Line/Fill tools, Scale converter, Light bake map, Construction (CAD), Model Painter, Import geometry, Script console), Settings (Lighting & rendering…), Help (Keyboard shortcuts…). The open variant's file name is shown at the right of the bar.
  • Left panel: the map picker, the Map Variant (.mvar) section (variant info, Forge labels), a searchable list of the objects in the open variant, and the Add Object palette with a 3D preview (lit like the viewport) you can drag into the scene. The fly-speed slider is in Settings ▸ Lighting & rendering….
  • Viewport: the 3D view with a small floating toolbar (Select / Move / Rotate / Construct) in the top-left corner.
  • Object window: a floating properties panel on the right that appears when something is selected.
  • Status bars: a one-line status message and, below it, the load progress plus the object budget (Objects: N / 651).

Where settings and projects live

The settings folder is:

  • Windows: %LOCALAPPDATA%\HaloMapStudio\
  • Linux: $XDG_DATA_HOME/HaloMapStudio/, or ~/.local/share/HaloMapStudio/ when XDG_DATA_HOME is unset.

It contains:

FilePurpose
project.mmsprojThe single "quick-save" slot (File ▸ Quick-save session / Restore last session, also the Quick-save / Restore buttons). A project stores the map path, camera position and an informational object list; it is JSON.
last_map.txt, last_variant.txtWhat to reopen on the next launch.
browser_bookmarks.txtBookmarked folders in the variant browser, one path per line.
forge_fx.txt, scaled_objects.txt, shadow_casters.txtThe Settings window's Forge special FX, Scaled objects and Shadow casters (Forge) switches (1 / 0; missing = on).
map_spawns.txt, physics_outlines.txt, wire_xray.txt, soft_ceilings.txt, hard_floor.txt, playable_bounds.txtThe View menu's Show map spawn points, Show physics outlines, Selection wireframe through objects, Soft ceilings, Hard floor and Playable BSP bounds overlays (1 / 0; missing = the default).

Named projects can be saved anywhere with File ▸ Save Project As… (.mmsproj) and reopened with File ▸ Open Project…; once a project has a name, File ▸ Save Project (name) re-saves it without a dialog. Opening a project restores the camera, reloads its map and variant, and restores any per-object SCALED / SHADOW overrides (they are not part of the .mvar). Lighting sliders and the geometry toggles are not persisted between runs; the five switches listed above are.
