Changelog

Release notes are published alongside each build on GitHub Releases. This page summarises them.

v1.6.0 — 2026-10-21 current

Halo 3 Forge editing that saves what Halo 3 stores, whole-build scaling, a character controller and vehicle physics taken from the engine, and a much lighter footprint next to the game. The properties panel on a Halo 3 map now edits Halo 3's own fields and writes them back; S scales a whole selection about its centre; test mode walks and drives on the engine's own laws; and Halo Map Studio stops running flat out when you are using something else.

Test mode and Theater remain labelled EXPERIMENTAL. Vehicle physics are still being matched to the engine, and ledge and edge behaviour is still under investigation. The tank and hover vehicles are not ported to the new physics yet. Theater sound levels are still being tuned, and Theater does not yet draw everything a clip recorded.

Added

  • Scale a whole build at once. "We need a way to take whole selections and scale them up and down, while maintaining their relative offsets to each other" -- so select as much as you like, press S, and drag to size it or type an exact factor. Everything scales about the selection's centre, so every piece keeps its offset from that centre in proportion and the build grows or shrinks as one thing. Orientation is left alone, because a uniform scale about a point does not turn anything. What it can and cannot do to the pieces themselves is reported rather than hidden, because Reach has no per-object scale field: an object's size is a community convention that overloads its spawn sequence, a single signed byte, and only applies to objects carrying the forge scale label. So only about 201 sizes exist per convention and the nearest is chosen by ratio -- the status line says how close it got ("sizes land within 1.8%"). An object with no scale label is moved but not resized, and counted, because its spawn sequence is real spawn ordering and overwriting it would change how the map plays. Objects past a convention's size ceiling are clamped, and counted. Halo 4 has a real scale field and does not share the quantisation.
  • Lighting on placed objects now follows the game's own probe lighting. Objects are lit from the map's sky and bounce light with the direction and first-bounce scaling the engine uses, and placed pieces now occlude and bounce light. Against the game's own probes on Forge World the light direction agrees far better than before. Objects can still look darker in the mid-tones than in the game, because the game's probes carry more sky light. This has been tested headlessly only, so tell us how it looks.
  • Halo 3 Forge: the map's own objects can now be edited. Objects that belong to the map itself show in the panel and can be moved or deleted, and new Forge objects take the first free slot. The object limit shown is what the map leaves free (640 minus the map's own objects). A 'maximum 100' on player spawns was the map's own spawns counting against it.
  • Theater: riders are placed in their vehicles and players take their team colours. Passengers and drivers recorded in a film now sit in their seats, and bipeds use the team's colours in team games.

Fixed

  • Halo 3 Forge: the properties panel edits what Halo 3 actually stores, and a save writes it. "We need to make sure all the features of the forge mode work properly and that map variants can be properly written to." The Object panel on a Halo 3 map was the Reach panel pointed at Halo 3 data: it offered cached type, a label picker, a parent picker, the Reach placement bits, an 11-bit boundary and (for player spawns, which share a number with Reach teleporters) a NATO teleporter-channel list -- edits that no Halo 3 save ever wrote. It now shows the Halo 3 Forge menu's own properties and every one is saved: the object's type (read-only), spare clips (weapons, grenades), teleporter channel, spawn order (spawns, hills, territories, flag and bomb spawns), symmetry, respawn time, team, and the boundary shape and size in world units. Changing symmetry touches only its two bits; the rest of the flags byte rides through. The bytes are the same ones the stock variants store: all 333 shipped variants (62,527 objects) load into the editor, save untouched, and come back byte-identical.
  • A freshly placed Halo 3 respawn zone, hill, kill zone or other shaped object was saved at size zero. The editor's copy of the new object disagreed with the record built from the tag's default size, and the save wrote the editor's zeros over it. Placed objects now keep the size the tag authors (19 shaped palette rows checked on Guardian alone).
  • Halo 3 boundary shapes were drawn about a hundred times too large. The overlay read Halo 3's 16-bit, 60-unit sizes as Reach's 11-bit, 200-unit ones, so a 15-unit zone drew roughly 1,600 units across.
  • Saving a Halo 3 variant no longer carries the template's stale bookkeeping. The per-item "placed on map" counts and the spent budget were copied from whatever file the save started from, so a new variant made from a stock map kept that map's numbers for objects it no longer had. They now move by exactly what the save added or removed (an untouched file is left bit-for-bit), and a blank new variant is recounted. The stored budget is capped at the variant's maximum, which is what every shipped variant does. What the game itself does with these fields is not fully known -- the stock files disagree with their own contents (the counts match on 87% of rows, the budget on 77 of 333) -- so this is the most defensible rule, not a reproduction of one.
  • Halo 3 now has a save check. Reach and Halo 4 hold a save that is about to clamp or drop something; Halo 3 saved silently. It now lists objects outside the variant bounds (double-click to fly to one; saving clamps them), items over their palette limit, a variant over budget, and objects that have no free slot or no palette row (those are not written). "Save anyway" or "Cancel". (Stock files do exceed a budget occasionally -- 11 of 333 hold more than their cap -- so that one is a warning, not a rule.)
  • The Halo 3 object counter and a budget meter. The status bar said "/ 651", which is Reach's slot count. A Halo 3 variant has 640 and the scenario's own objects take the first 278 to 331 of them, so it now shows what is actually left, plus Budget: spent / maximum.
  • Scale (S) on a Halo 3 map says what it does. A Halo 3 object has no size field at all, so scaling a selection there moves the objects and cannot resize them; the status line now says so instead of blaming a missing "scale" label.
  • Theater: a clip name with no : in it crashed the class lookup. class_of_clip evaluated its index before testing the length. It surfaced when a newer film produced a one-part name.

Test mode (experimental)

  • Walking and slopes now use the engine's own character controller. "My biped can't even walk up a set of stairs or a simple ramp without jittering." The old controller snapped the body's height to a probed value every frame with two formulas fighting each other; the engine never moves the body to keep it grounded -- it adds a small velocity into the ground plane. Ramps and stairs no longer jitter, a surface steeper than 35 degrees is not walkable whatever you push, walking over the seams between floor triangles is smooth, and in the air your velocity now bleeds toward the stick at the authored airborne acceleration instead of coasting for free. Strafe, crouch and sprint follow the authored curves: crouch blends speed and acceleration by how far down you are, and sprint waits its authored start time and then eases in. Jumps keep full gravity (the half-gravity write the engine makes never reaches a player).
  • Warthogs and Mongooses drive on the engine's own vehicle physics. Each wheel carries its share of the weight on a spring and tyre friction decides how the vehicle accelerates, brakes, slides and turns, instead of the old kinematic model that pivoted on a dime. A parked vehicle does not turn when you steer, hard cornering at speed breaks the tail loose, the Warthog tops out at 11.4 and the Mongoose at 8.8 wu/s, a reverse press while moving brakes before it reverses, slopes up to about 40 degrees hold a stopped vehicle and steeper ones slide it, and landings after big jumps are caught by the suspension. They steer toward where the camera looks, as the engine does (the steer angle really is up to 60 degrees; the 30 degrees seen in the steering animation is only art). The tank and hover vehicles are not on this yet.
  • Getting into a vehicle plays the real boarding animation and the camera glides to the vehicle's own chase camera over about half a second, following the seat's authored camera track (it drops as you look up and keeps off walls). The controls stay dead until the climb finishes. Getting out plays the exit animation, puts you on the ground and glides back to first person. A vehicle you leave stays exactly where you parked it instead of vanishing and respawning at its starting spot (that was the "duplicate vehicle"), and you can climb back into the same one. The driver's hands follow the wheel and handlebars, gunner seats sit in the turret frame (they were 0.69 wu out), and your own gun no longer fires from inside a vehicle.
  • The physics tick is 60 Hz, as in the game. Test mode's physics clock was half the real rate. Gravity, acceleration, the sprint curve and the vehicle timers now run on the engine's tick.
  • Rigid-body groundwork from the engine's Havok build (reach_havok): the engine's world settings (solver, tolerances, continuous simulation), damping and velocity caps, per-vehicle gravity scale (Banshee 0.75, Falcon 0.95, Sabre and Seraph 0.3, jeeps 1.0), and the friction / restitution mixing rules are decoded and gated. None of it changes what you see until vehicles are wired to it.

Performance

  • Halo Map Studio no longer runs flat out while you are using something else. "We essentially want to make it not a pain to run it alongside MCC" -- and it was a pain, because the editor had no idea whether anyone was looking at it. Alt-tab to the game and HMS carried on doing the whole thing: the full update(), the full offscreen 3D render, and a command submission of 4,349 draw calls, sixty times a second, for a window behind the game. It now redraws a few times a second while its window is not the one you are using, and slower still when it is minimised or completely covered. Measured in production with the window left behind another app: 406 scene frames drawn and 391 skipped, i.e. the viewport was being redrawn about ten times a second instead of at the display's rate. A film keeps PLAYING and keeps its timing -- the playback clock runs on real elapsed time, so nothing drifts and nothing pauses; it is simply drawn less often. Settings > Graphics > "Throttle when not in focus", on by default, turn it off if you keep playback running on a second monitor. The saving is not only frames: the particle simulation, the 3D render and the exposure metering are each skipped on a frame nobody can see, so a background frame costs the interface and nothing else.
  • A new install now renders at 100% instead of 200%, which is most of the answer to "are we hogging the GPU". We were, and now there is a number for it: per-pass GPU timing of a real playback frame says HMS asked the graphics card for 10.7 ms a frame, 9.9 ms of it the scene pass -- roughly two thirds of a high-end card at sixty frames a second, with a game running. The reason was the shipped render scale. HMS has always drawn the 3D scene at 200%: true 2x supersampling, four times the pixels. Nobody chose that; it was simply the default. New installs render at 100%, and 200% is still there under Settings > Graphics > Render scale for screenshots and calibration work, where four times the pixels is exactly what you want. An existing install keeps whatever it already has -- a saved 200% is indistinguishable from someone who picked it deliberately, so nothing is migrated and nobody's picture changes under them; pick Medium, or set Render scale yourself, to take the new default. Measured on the same clip at the same tick, before and after: 10.71 ms of graphics-card time a frame at 200% (9.90 ms of it the scene pass) against 3.93 ms at 100% (3.40 ms scene) -- 2.7x less GPU asked for, and 2.9x less of the scene pass. Worth being clear about what this does and does not change: render scale is resolution only. It does not touch the calibrated lighting, exposure or tonemap laws, so the entire difference is how jagged an edge looks -- not the colour of anything. HMS's own frame RATE, separately, is limited by the processor rather than the card (33.9 ms of a 34.6 ms Theater frame was CPU inside one update()), which is why the background throttle above is the thing that actually gets HMS out of a game's way. Both were true at once. (Headless captures are deliberately unchanged and still render supersampled: they never go through the Graphics settings, and every calibration reference image in this project was taken that way.)
  • Theater: "FPS is terrible in the theater playback", and "the program is EXTREMELY laggy now in theater mode". It is, and it was CPU, not the graphics card: measured on the 7-minute 16-player Forge clip with nothing else running, a playback frame took 34.6 ms (28.9 fps), with a 75.7 ms p99 and a worst frame of 157.8 ms -- and 33.9 of those 34.6 ms were the CPU inside one update(), so the GPU was idle waiting for it. Worse, the cost DEPENDED ON HOW FAR INTO THE CLIP YOU WERE: the same clip at 1:00 ran at 30.2 ms a frame and at 7:00 at 99.8 ms, which is the "it gets laggier the longer you watch" nobody could pin down. Theater now reports its own frame times (film perf, below) so none of this has to be guessed at again, and four costs are gone from the per-frame path:
    • The animation PHASE was re-integrated over each body's entire past, every frame. What drives a body's walk cycle is the ground it has covered, and that was computed by walking every position sample the recording holds for it from the start of its life up to the playhead -- once per drawn body, once per frame, so one frame's cost grew with the playhead. It is a running total, so it is now accumulated once and read with a binary search. The number that comes out is bit-for-bit the same f32, not an approximation, which matters more than the speed does: the phase decides the pose, and a Theater frame has to be a pure function of the playhead or the same tick reached two different ways would look different. A gate asserts the bit equality over 701 ticks of a track containing respawn teleports, repeated ticks, gait changes and stand-still stretches.
    • Every corpse on the ground was fully animated before being overwritten. A ragdolled body's joints come from the physics solver, but the clip was still sampled, cross-faded, overlaid and chained up the skeleton first -- and then the solver's pose overwrote all of it, line for line. Up to fourteen bodies lie on the ground at once, each paying for a pose nothing could see.
    • Every posed body re-sorted its own skeleton, every frame. Composing a pose needs parents before children, and that order was recomputed -- two allocations and a comparison sort of all ~130 nodes -- on every body on every frame, for an answer fixed when the model was decoded.
    • A settled ragdoll re-scanned the whole placed-object table every frame. The physics step returns immediately once a body is asleep, but the collision geometry it would have needed was gathered first: with fourteen corpses down, fourteen scans of every Forge piece on the map per frame, for a result nothing read.
  • Theater: film perf now reports the whole playback frame, as a distribution. Mean, median, p95, p99 and worst frame for both the frame period and the CPU inside update(), then every one of seventeen stages of a Theater frame with its mean, its share, its own p99 and its worst -- plus the five phases inside the body placement and the frame's draw-call census. "Laggy" is a complaint about the worst frames, not the average, and an average hides them. film perf reset empties the ten-second window so a change can be measured without restarting. Always on while a clip is open; the whole cost is seventeen clock reads a frame.

v1.5.0 — 2026-10-14

Walk around the map you are building. This release adds a playable test mode — turn into a Spartan or an Elite, walk, jump, crouch, sprint, melee, pick up and fire the map's own weapons, and drive its vehicles — together with the game's own HUD, Theater sound, and a large amount of reverse-engineering behind all of it.

Test mode and Theater ship labelled EXPERIMENTAL. Both are real and worth using, and both are incomplete. Test mode's movement and vehicle physics are still being matched to the engine, so expect rough edges on slopes, stairs and while driving. Theater decodes a great deal correctly but does not yet draw everything a clip recorded. The menus say so.

Test mode (experimental)

  • Play on the map you just built. Play ▸ Play as Spartan / Elite spawns a biped at your camera and hands it the viewport. First person by default, T for third person, Esc to leave — and leaving puts the camera where you walked to, not back where you started. The editor's panels and toolbars hide while you play.
  • Nothing about how it moves was invented. Walk, run and sprint speeds, acceleration, jump velocity, capsule and eye heights, turn rates, the maximum slope and the crouch transition time are all read from the map's own bipd and matg tags, per species and per stance.
  • Weapons. Walk up to anything lying on the map and pick it up, or take one from the menu; fire it, melee with it, and reload it with R. The magazine counts down and reloads from a real reserve, at the weapon's own authored sizes.
  • Vehicles. Walk up to a vehicle and get in — the prompt is the game's own localised text with your own bound key. Vehicles sit on the ground they are on, have real suspension, and a Warthog's speed comes from its engine, gearbox and wheels rather than a number nobody authored. Wheels roll, steering turns, and a turret gunner's gun follows their aim.
  • Animation. Directional locomotion is blended rather than switched: the body picks up to four of the game's own clips, weighted by how fast and which way you are actually travelling. Idle, turn-in-place and crouch transitions run at their authored timings.

The in-game HUD

  • Test mode draws Reach's own HUD, from the game's chud tags on the engine's own virtual screen: shield and health bars at the biped's authored values, the held weapon's reticule and ammunition, grenade counts, the ridden vehicle's own HUD, and button prompts carrying the key you have bound.
  • Two authored render fields that had never been read — each widget's shader type and blend mode — are now honoured. Among other things the shield bar was being painted out by its own additive border, in Theater as well as in test mode.
  • What is deliberately not drawn is listed rather than faked: no motion tracker (there is nobody else on the map, so every blip would be invented), no vehicle condition meters, no respawn timer.

Theater (experimental)

  • Sound. Weapon fire, melee, reloads, footsteps and the map's own ambience, decoded from the game's banks and positioned by the engine's own rules.
  • Projectiles, muzzle flashes, trails and detonations are drawn on the paths the film recorded.
  • Armour effects — flaming helmets, thunder clouds and the rest — now play, and a held energy sword's blade glow and handle plasma with them.
  • Two transport buttons jump to the next or previous assassination and put the camera on the victim.
  • Runs are drawn as runs. Full-speed movement used to be drawn as a walk and a sprint could never be drawn at all.
  • Opening a film whose map was not already loaded used to load the map and then do nothing roughly three times in ten. Fixed at the cause.

Performance

  • Halo Map Studio no longer runs flat out while you are using something else. It redraws a few times a second when its window is not the one you are using, and slower still when minimised or covered. A film keeps playing and keeps its timing. Settings ▸ Graphics ▸ Throttle when not in focus, on by default.
  • A new install renders at 100% instead of 200%. The 3D scene had always been drawn at true 2× supersampling — four times the pixels — which nobody had chosen. Measured: 10.7 ms of GPU time a frame down to 3.9. 200% is still available under Render scale, and an existing install keeps whatever it already has.
  • Theater playback is no longer slower the further into a film you are. The cost of a frame had been growing with the playhead; at six and a half minutes in, playback is 59% faster.

Also

  • Import your controls from MCC — Settings ▸ Controls & keyboard ▸ Import reads your own Master Chief Collection settings, shows exactly what it would change before changing anything, brings your bindings and your field of view across, and can be undone. Your MCC files are never written to.
  • Your first-person arms, legs and gun are lit the way the engine lights them. Reach has no separate first-person lighting rig: a viewmodel is lit as the object it belongs to, and HMS had been feeding that path a render model where an object belonged.
  • Reach's own in-game text can be read at last, which is how the vehicle prompts, the HUD's words and the button glyphs come out right.

v1.4.0 — 2026-10-12

The last public release was v1.2.2; v1.3.1 was prepared and never published, so this release carries both halves. The headline additions are Halo 3, Halo 2 Anniversary editing and Halo Reach Theater.

Theater — Reach saved films

  • Saved films open and play. File ▸ Open theater clip… loads a Reach .mov (including the in-progress .temp recording of a match you are still playing), draws the film's own Forge map, and plays the recording back with transport controls, a scrub timeline (View ▸ Theater timeline), free / follow / over-the-shoulder / first-person cameras and a cast list. See Theater.
  • Players are the characters they really were. Each body is drawn as the biped the recording names — Spartans and Elites — skinned and posed by the game's own animation graphs, wearing the armour, the armour effect and the colours that player had chosen, and holding the weapon the recording gives them (including the weapon the gametype's loadout spawns them with).
  • Movement from the recording, not guessed. Walk, run, back-off and strafe cycles are driven by measured stride rates per weapon class; idle clips play at the engine's 30 fps (they used to run nearly eight times too fast); players ride, enter and leave vehicles; melee swings, weapon fire, reloads and assassinations are read off the film's own event channel rather than inferred from how a body moved.
  • Deaths. A killed player plays the ragdoll clip their own character has (the Elite's is named differently, which is why Elites used to stay standing), falls to the floor under the gravity measured from the recordings, and lies where they fell until the recording itself removes them — several seconds, as in game — instead of vanishing after five.
  • First person. Looking through a player's eyes draws their own arms and the weapon in them, both posed by that weapon's own first-person animation, with the player's forearm and chest pieces on the hands. Each species has its own arms.
  • The game's own HUD. The player list is built from Reach's own scoreboard widget tags, and floating player names use Reach's own font, team-coloured, with no background plate — both read from the game's assets rather than drawn by us.
  • Statistics. Theater ▸ Statistics and --film-stats report per-player time, distance, weapons, vehicles, deaths and the match score out of the recording, and name who was responsible for about nine deaths in ten.
  • What a recording does not contain is now said plainly rather than silently approximated: a Reach film records only the recorder's own kill feed, most medals and assists are absent, one body per clip has a live look direction, and a clip can hold more players than it holds gamertags.

Halo 3

  • Maps open in the viewer — textured clusters and instances, baked lightmaps, skies, fog, scenario objects and object lighting from the map's light probes.
  • Map variants open in the editor with the map's Forge palette, attachments, water and damage states, and save byte-for-byte against every shipped variant.
  • You can place objects. Dragging a palette piece into the viewport, the Line and Fill tools and the place verb all used to refuse silently unless a variant was already open; a shipped variant is now adopted as a blank canvas.
  • Lighting is no longer about a fifth too dark. Halo 3 was being put through Halo Reach's tone curve; it now uses its own (1.5c − 0.5c³), which lifts everything below white by about 22%.

Halo 2 Anniversary

  • Map variants can now be saved. H2A was read-only. Its variants now open, edit and save through the full Halo 4 editor, and HMS reproduces 283 of the 289 shipped H2A variants byte-for-byte (the six are duplicates of two files whose own stored checksum matches no formula over their payload — MCC never checks it).
  • All seven maps surveyed and fixed: skies, ocean tint, layered material families, fog and the fallback sky gradient.

Halo 4

  • Exposure and bloom follow the engine chain, Forge lightmap burn shadows, object lighting from surface and air probes, an exposure override in the GUI, the grid family, a faster sky and fog.

Editing

  • Prefabs. Save a selection as a reusable building block (.hmsprefab) and drop it into any map, in any supported game. Tools ▸ Prefabs.
  • Every control can be rebound. Settings ▸ Controls & keyboard lists all 38 editor actions, with left-handed presets; flight keys bind by physical position, so AZERTY and Dvorak layouts work.
  • Convert a map variant to another game. File ▸ Convert variant to another game… re-creates a Forge map on another title's canvas. All four titles work as a source and as a target, and every piece that cannot be re-created is reported with the reason rather than quietly left out.
  • Save precision preview. A ghost of the pose a save can actually store, plus snap-to-representable — rotation is the big loss (a Halo 3 facing angle is eight bits).
  • Damage states. The Object panel shows an object's damage state (minor … destroyed); kept in the project, never written to the .mvar.
  • Spawn camera and physics settle. The camera opens on the variant's spawn points; placed objects can be settled onto the ground with the map's collision.
  • Model import. Imported geometry keeps its materials, is selectable and movable like any other object, and is browsed through the same file picker as everything else.
  • Open recent lists what you last opened — variants, base maps, projects and theater clips.

Rendering

  • Forge pieces have their reflections, and the shine nothing asked for is gone. Every Forge object was shaded with the material constants of its first part, so a reflective catwalk was matte and a plain platform had a sheen the map never authored. Each part now carries its own specular, roughness and environment map, read from the object's own materials.
  • The energy sword has its two glowing blades (five additive layers, three of which were being discarded), and energy blades and vehicle accent lights no longer have their red and blue exchanged.
  • Parked Forge vehicles no longer glow with lit headlights, brake lights and dashboards.
  • Weapons and equipment lying in a map are the size the game draws them — about a third larger than before — and a held weapon is the size the weapon tag states for that player's species.
  • Solid barriers no longer draw see-through, and switching a damage state no longer leaves other states untextured.
  • Forge objects appear much faster instead of trickling in one at a time; Theater playback on a busy 16-player clip is several times faster and no longer grows in memory as it plays.

Other

  • Modded and Workshop maps. Maps installed from the Steam Workshop no longer load with missing geometry: the parser could not find MCC's stock shared.map (it only looked beside the map), so every model paged out of the shared cache failed to decode. Variants saved against a Workshop map are routed to the right base map by its MCC map GUID instead of the -2 placeholder the file carries. Load time for a large modded map dropped from 47 s to under 8 s.
  • Graphics & performance settings. A Settings page that trades picture quality for speed: presets, render scale, shadow / post / texture / draw-distance knobs, a frame cap and an idle throttle.
  • Auto-update (opt-in). The app checks GitHub Releases once a day and shows a small Update available pill next to Help; the Update window downloads the archive, verifies it, installs it after you close the app and restores your session (see Updating). Settings ▸ Updates turns the check off.
  • Linux. Maps are found on udisks-mounted drives and in the Xbox app's layout, not only under Steam; settings and projects use XDG paths instead of a Windows-only environment variable.
  • Version numbers: the app, the archives (HaloMapStudio-1.4.0-<platform>.zip plus .sha256) and these pages now share one version.

v1.1 – v1.2 — 2026-09-16 / 2026-09-22

Released as the v1.1.x pre-releases and v1.2.1 / v1.2.2 on GitHub; the list below is what they added over v0.1.0.

  • Variant properties. Every global field of a map variant (Reach and Halo 4) is now decoded and shown in a Variant properties group of the left panel - ids, stamps, activity / mode / engine, category, budget, flags, the world bounds, the chunk length / SHA-1 / _fsm and the per-piece quota table with palette names - with the engine's field names on hover; category, maximum budget, world bounds (behind a warning) and quota min / max are editable; variant get / variant set do the same from scripts. Reach saves now write a correct mvar chunk length and SHA-1 and mirror header edits into the chdr chunk (both were left stale before). See Variant properties.
  • Halo 4 Forge editing. A Halo 4 map variant now opens as an editable scene: select / box-select with the outline, G / R, gizmo, Shift+D, Delete, undo / redo, drag-and-drop placement from the map's own Forge palette (localised names, the game's placement defaults per piece), the Object panel with the Halo 4 record (quota / variant, team and colour, object type, spawn order / time, four labels, parent, placement bits, shape in world units, type extras, a raw (unverified) group and an editor-only scale), mass edits, and place / set / get / save as in scripts. File ▸ Save writes the open .mvar in place and Save As writes a new one, both through the engine's own encoder after a save check (objects outside the variant bounds are clamped, stale types are reported; the budget and the palette maxima are not checked, because the game ignores both). The encoder reproduces every shipped variant byte-for-byte and an HMS-saved variant loads in MCC. See Halo 4.
  • Halo 2 Anniversary (early, view-only). MCC's groundhog caches load through the same pure-Rust reader as Halo 4 (the format is identical apart from one pointer constant): the map picker gains a Halo 2 Anniversary group, and the maps render with their geometry, textures, baked lightmaps and post chain. Map variants are not yet decoded, so it is view-only for now.
  • Forge special FX. Placed special-FX objects (Colorblind, Gloomy, Juicy, Nova, Olde Timey, Pen and Ink, Dusk, Eerie, Golden Hour) now apply their screen effect, composed like the game. Settings ▸ Forge special FX (persisted), script screenfx on|off|get, headless HMS_FORGE_FX=0.
  • SCALED / SHADOW pseudo-flags. Per-object checkboxes in the Object panel with (auto) / (set) state (right-click resets to automatic), stored in the project rather than the .mvar; [scaled] / [shadow] markers in the objects list; global switches Scaled objects and Shadow casters (Forge) in Settings (persisted). Scripts: set … scaled|shadow on|off|default, scale, shadowcasters, flags; headless HMS_SCALED, HMS_SHADOWCASTERS.
  • Objects outside playable space. Objects inside a BSP flagged "not normally playable space in multiplayer" get an orange ! in the objects list and a warning strip in the Object panel; Save / Save As first show a window listing them (double-click a row to select and fly there; Save anyway). Script bspwarn list.
  • Soft ceilings (map floor). View ▸ Soft ceilings (map floor) draws the invisible planes that bound a Reach map's playable space — the floor under Forge World, the outer walls and the sky ceiling — as a translucent fill plus edges that show through the terrain and water (red = soft kill, orange = acceleration, yellow = slip surface). Off by default, persisted (soft_ceilings.txt); script softceilings on|off|get (get lists every ceiling); headless HMS_SOFT_CEILINGS=1. Trigger volumes moved from Settings to the View menu (script triggers on|off|get).
  • Hard floor (world bounds). View ▸ Hard floor (world bounds) draws the map's world box — the physics broadphase the game builds from every structure BSP's bounds (sky and hidden BSPs included) plus 64 units, the invisible wall nothing can pass — as a magenta box with its floor gridded at the lowest height (Forge World: -75, where you stop with the soft ceiling off). View ▸ Playable BSP bounds draws the smaller per-BSP boxes (violet). Both off by default, persisted (hard_floor.txt, playable_bounds.txt); scripts hardfloor, playablebounds; headless HMS_HARD_FLOOR=1, HMS_PLAYABLE_BOUNDS=1.
  • View menu overlays. Show map spawn points (the base map's own spawn markers, off by default) and Show hidden-block physics hulls (the variant's invisible blocks, on by default; never map objects or level geometry), both persisted; scripts mapspawns and outlines; headless HMS_MAP_SPAWNS, HMS_PHYSICS_OUTLINES.
  • Teams. The team drop-down lists neutral (no team) first and none (unset) last; new objects start on the neutral team, as in the game. Script set … team accepts names (red … pink, neutral, none).
  • Hidden blocks are real objects. Click the hull to select an invisible block, box-select takes every block whose hull overlaps, the selection wireframe is the hull, and magnet / face mates / array duplicate use the hull extents so copies tile edge to edge.
  • Scripting. New verbs select box, undo, redo (GUI), outlines, mapspawns, screenfx, scale, shadowcasters, flags, bspwarn; the console's built-in quick reference now lists every verb.
  • Camera and preview. The cursor is hidden and captured while flying with the right mouse button and while moving / rotating objects (locked on Windows and Wayland, confined on X11). The palette's 3D preview renders through the viewport's object path, with the map's lighting.
  • Rendering. Engine-exact Forge lights and power-ups, armor-ability pickups, vehicles with their attachments, the Tree of Life and foliage, water categories, decals and per-object lighting.
  • Settings. Fly speed and the camera stand-off live in Settings ▸ Camera, render & display; diagnostics under Advanced. Settings files: forge_fx.txt, scaled_objects.txt, shadow_casters.txt, map_spawns.txt, physics_outlines.txt.
  • Earlier: left panel reorganisation, searchable variant object list, placement tools moved to the Tools menu, Edit and View menus, Help ▸ Keyboard shortcuts as the shortcut reference.

v0.1.0 — 2026-09

First public binary release (Windows x64 and Linux x64 archives). Source code is planned to follow once the renderer and the Forge editing workflow settle.

  • Halo: Reach map viewer with engine-faithful lighting, materials, water, sky, fog and effect particles; automatic discovery of Steam and Workshop maps.
  • Forge variant (.mvar) open / edit / save, including Forge properties, labels, parents, boundaries and the 651-slot budget.
  • Blender-style editing (grab / rotate / duplicate, axis locks, magnet, precision, array), gizmos, box select, mass edit, undo/redo, Line and Fill placement tools.
  • Construction (CAD) tools: guides, circles, squares, face-to-face mate, anchor, mirror, fill edge.

  • Headless PNG rendering (HMS_SHOT), --dump-maps and variant inspection flags.
  • Optional real-time probe GI and a path-traced lighting bake.
  • Halo 4 support: engine-faithful rendering and Forge variant editing (open / edit / save), read with a pure-Rust cache parser.
  • Projects (.mmsproj) and a quick-save session slot; settings stored per user.
