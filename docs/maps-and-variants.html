How maps are found

On start-up (and whenever you press the ↻ rescan button) the app looks for MCC in this order:

  1. HMS_MCC_DIRS — an optional environment variable with one or more paths separated by ;. Each entry may be the MCC root, a haloreach / halo4 folder, or a maps folder. This is added on top of the automatic search, it does not replace it.
  2. Steam libraries. The Steam install is located (Windows: registry; Linux: ~/.local/share/Steam, ~/.steam/steam, ~/.steam/root, the Flatpak location, or $XDG_DATA_HOME/Steam) and every library in steamapps/libraryfolders.vdf is scanned for steamapps/common/Halo The Master Chief Collection/haloreach/maps and …/halo4/maps, plus the Workshop folder steamapps/workshop/content/976730 (searched recursively).
  3. Xbox / Microsoft Store installs (<drive>:\XboxGames\…\Content\haloreach\maps, …\Program Files\ModifiableWindowsApps\…) — only when no Steam copy was found, and only on Windows.

Resource caches that are not playable maps (shared.map, campaign.map, single_player_shared.map, bitmaps.map, sounds.map, loc.map, mainmenu.map) are skipped. A Workshop item is only listed if its ModInfo.json says it is a Halo: Reach or Halo 4 mod (items for other MCC games are ignored).

Maps are shown by their scenario name (for example forge_halo, 45_aftship), not by the in-game display name. Workshop maps carry a [Workshop <item id>] suffix and Halo 4 maps a [Halo 4] suffix. Forge canvases (forge…) sort first, then the rest alphabetically.

Run hms-app --dump-maps from a terminal to print every detected map with its id, group and full path (see Headless / CLI).

Map picker groups

  • Built-in (N) — every .map in the game's own haloreach\maps folder. This includes the Anniversary cex_* maps and any copies you have dropped into that folder yourself: the grouping is purely by folder.
  • Modded (N) — maps found under the Steam Workshop folder.
  • Halo 4 (experimental) (N) — Halo 4 caches from halo4\maps and Halo 4 Workshop items. Only shown when at least one exists. See Halo 4 (experimental).

Loading a map

Select a map in the drop-down and press Load selected map. Reload re-opens the cache and rebuilds everything; Reload forge rebuilds only the Forge objects and keeps the level geometry. The bottom bar shows Loading map… N%. On Forge World the first load takes several seconds and a few gigabytes of RAM while textures are decoded.

The Add Object palette in the left panel is filled from the loaded map's Forge palette (its "sandbox" palette), grouped by Forge category, with a filter box and a 3D preview of the selected item.

Forge map variants (.mvar)

A map variant is the file Halo: Reach writes when you save a Forge map: it lists the placed objects (up to 651) with their position, rotation, team, colour, label, spawn settings, boundaries and so on, plus a title, description, author and a table of Forge labels. Halo Map Studio reads and writes the Reach format (mvar chunk version 31). Halo 4 variants (version 50) can be opened read-only.

Where MCC keeps variants

LocationContents
<MCC>\haloreach\map_variants\Variants shipped with the game (for example the Forge World variants such as Asylum).
<MCC>\haloreach\hopper_map_variants\Matchmaking variants shipped with the game.
%USERPROFILE%\AppData\LocalLow\MCC\LocalFiles\<XUID>\HaloReach\Map\Your own Forge saves. <XUID> is a long numeric folder per Xbox Live profile. A temp\ subfolder holds temporary saves.
Linux (Proton): …/steamapps/compatdata/976730/pfx/drive_c/users/steamuser/AppData/LocalLow/MCC/LocalFiles/<XUID>/HaloReach/Map/The same folder inside the Proton prefix.

All of these appear as quick links in the variant browser's Game section (🎮 map_variants, 🏆 hopper_map_variants, 👤 HaloReach · <profile>). Only folders that exist and contain at least one .mvar are listed. If your saves live elsewhere, set HMS_MCC_LOCALFILES to one or more MCC\LocalFiles roots (separated by ;), or just navigate there in the browser.

Opening a variant

  1. File ▸ Open .mvar… opens the built-in file browser (it is not the OS dialog): back/forward/up/refresh buttons, an editable path box, a search field, and a sidebar with Bookmarks (add the current folder with ＋), Game quick links, System folders, Volumes and Recent. Columns can be sorted by name, date or size.
  2. Single-click a file to preview its Title, Author, Editor and Description before opening. Double-click or press 📂 Open.
  3. If the variant belongs to a different map than the one loaded, the app loads that base map first (matched by the map id stored in the variant) and then places the objects. If the base map is not installed the variant is rendered best-effort on whatever map is loaded.
  4. The camera jumps to one of the variant's initial spawn points, facing the way a player would.

The status line then reads for example asylum.mvar: 458 forge objects (0 unresolved …) in 312 ms. "Unresolved" objects are entries the app could not match to the map's Forge palette; they are not displayed but still occupy their slots and are preserved on save. Details are written to hms_mvar_diag.txt next to the executable.

The left panel shows the objects of the open variant as a searchable list (search by type, name, label or #slot): click to select, Ctrl/Shift-click for multi-selection, double-click to fly the camera to the object. Clear removes the rendered variant objects from the scene.

Variant info and Forge labels

With a variant open, the Map Variant (.mvar) section has two collapsible groups:

  • Variant Info — Name, Description, Author and Editor (the "created by" / "modified by" gamertags, 16 characters max). Edits are written by the next Save.
  • Forge labels — the variant's label table (the names you assign to objects for game types, such as ctf_flag_return). You can rename, delete (🗑) and add labels; new labels can also be created straight from the Object panel.

New variant

File ▸ New variant starts an empty variant for the loaded map. Because an .mvar needs a valid header for that specific map, the app copies the header of the smallest existing variant it can find for the same map id (from map_variants, hopper_map_variants or the last folder you opened). Set the name and description, place objects, then Save — the first save asks for a file name.

Saving

File ▸ Save overwrites the open .mvar in place and does not create a backup. Use File ▸ Save As… to write a new file, or copy the original first. Never save over a file while the game has it open.

What a save does:

  • Every part of the file that is not the object list (the BLF container chunks, the header, the title/description/author unless you edited them, the label table unless you edited it) is copied byte-for-byte from the original.
  • Objects are written in the editor's order into slots 0…N. Objects you did not touch round-trip bit-exactly; rotations are only re-quantised for objects you actually rotated. Deleted objects free their slots; if a deleted object was the parent of another, the child is left without a parent.
  • Objects the app could not display are still written back unchanged.
  • The per-type quota table is updated (placed on map recounted; max raised if you exceeded it).
  • New objects whose palette entry cannot be resolved are dropped, and the status line tells you how many.

The status line confirms with Saved N objects → file.mvar. Halo 4 variants are read-only; Save is disabled for them.

The Scale converter (Tools ▸ Scale converter…) is a related utility: it rewrites the spawn-sequence encoding of every SCALE-labelled object from one community scaling convention (1×, 33×, 71×, 47× or 330×) to another. Only the spawn sequence changes; save afterwards to persist it.

The 651-object budget

A Reach variant has exactly 651 object slots. The bottom-right of the window shows Objects: N / 651 (yellow at 90 %, red when full). Objects that are in the file but not displayed still count. When the variant is full, newly placed objects cannot be saved: the status line reports how many had no free slot.
